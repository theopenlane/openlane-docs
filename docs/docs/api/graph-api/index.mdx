# Using the Openlane API

The GraphQL API is the primary programmatic interface to Openlane: every object you work with in the console (controls, risks, campaigns, vendors, evidence) is available through a single endpoint with a strongly typed schema. A smaller [REST API](../rest-api/openlane-openapi-3-1-1-specifications.info.mdx) covers authentication flows, account operations, and System for Cross-domain Identity Management (SCIM) provisioning.

## Endpoint and Authentication

All GraphQL operations are HTTP POST requests to:

```
https://api.theopenlane.io/query
```

Authenticate with a bearer token in the `Authorization` header. Two token types exist: organization-scoped **API tokens** for integrations and automation, and user-scoped **personal access tokens** for personal tooling; [Programmatic Access](/docs/platform/settings/authentication/programmatic) covers creating each and when to use which.

:::info
Creating tokens requires your organization to have a payment method on file.
:::

```bash
curl -H "Authorization: Bearer $OPENLANE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "query { organizations { edges { node { id displayName } } } }"}' \
  https://api.theopenlane.io/query
```

## Exploring the Schema

The schema is large (every object, filter, and mutation in the platform), so the right way to browse it is interactively rather than through static pages. The [GraphQL Explorer](/graphql) gives you the full, always-current schema with search, documentation for every field, and a query builder you can run authenticated requests from: set your `Authorization` header in the Headers tab and everything you compose runs against your real organization.

For the recurring patterns that apply across the whole schema (pagination, filtering, ordering, mutations, and bulk operations), see [Schema Conventions](./conventions.mdx); one read covers the machinery every query shares.

## Worked Examples

Per-domain examples with complete queries and mutations live in the developer docs:

- [Organizations](/docs/developers/graphql-examples/organizations), [Groups](/docs/developers/graphql-examples/groups), and [Permissions](/docs/developers/graphql-examples/permissions)
- [Controls](/docs/developers/graphql-examples/controls), [Evidence](/docs/developers/graphql-examples/evidence), and [Programs](/docs/developers/graphql-examples/programs)
- [Risks](/docs/developers/graphql-examples/risks) and [Tasks](/docs/developers/graphql-examples/tasks)

The object pages throughout the platform docs also carry `Examples` sections with CSV, GraphQL, Go client, and CLI variants for their object.

## Clients

The [Go client](https://github.com/theopenlane/go-client) is generated from this schema and is what the [CLI](https://github.com/theopenlane/core/releases) is built on. For other languages, any standard GraphQL client works against the endpoint; introspection is enabled, so codegen tooling can generate types directly from the API.
