# Tasks

Tasks are the individual pieces of work that keep your compliance program moving: collect this <Term t="evidence">evidence</Term>, review that policy, remediate this <Term t="finding">finding</Term>. Each task has an owner, a due date, and links back to the objects it's about, so the work and the context stay together, without a separate tracker on the side.

The goal is that your team logs into Openlane and knows what's due, who owns it, and what it relates to.

Missed compliance work is easy to overlook: an access review that slipped a quarter, evidence nobody collected in March. Tasks give every piece of recurring work clear ownership and a deadline, and completed tasks become part of your audit trail: proof the work happened, when, and by whom.

The home dashboard surfaces tasks that are due soon, so the answer to "what needs doing?" is the first thing people see when they log in.

## Where Tasks Come From

- **Created directly**: from the [Tasks page](https://console.theopenlane.io/tasks), with a title, type, assignee, due date, and any related objects
- **Created from another object**: open a control, risk, or policy and create a task from there; the link back is made automatically. This is the most common path: you spot a gap while looking at a control, and the follow-up work is one click away.
- **From a template**: reuse a [task template](#task-templates) for repeatable work like offboarding an employee, with the details and linked objects already filled in
- **Bulk imported**: [upload a CSV](../importing-data.mdx) to create many tasks at once, like a full set of evidence-request tasks at the start of an audit period

## Creating a Task

Create a task from the [Tasks page](https://console.theopenlane.io/tasks) with **Create** → **From Scratch** (or **From Template**, see [Task Templates](#task-templates)), or from the object that needs the work. Two fields on the form warrant explanation:

- The **Type** list (Evidence, Risk Review, Policy Review, Other) is customizable through [custom data](../settings/custom-data.mdx), so it can match how your team categorizes work
- **Associated objects** are what carry context to the assignee. A task linked to its control tells them exactly what evidence goes where; an unlinked task makes them reconstruct that from the title.

### Task Templates

Some work repeats with the same shape every time: offboarding an employee, onboarding a vendor, running the quarterly access review, prepping for an audit kickoff. Instead of rewriting those tasks from scratch, save them as templates and create new tasks from them.

A template is a task with **This is a template** turned on. It keeps the title, type, details, assignee, tags, and associated objects, so the instructions and the controls or policies the work relates to come along every time.

To create a template:

<Steps>

1. On the [Tasks page](https://console.theopenlane.io/tasks), select **Create** → **From Scratch**
2. Fill in the task the way you want every copy to start, for example an "Employee offboarding" task with the offboarding checklist in the details, linked to your access control policy and the relevant controls
3. Turn on **This is a template**
4. Click **Save as template**, or **Save as template and use** to also create the first task from it right away

</Steps>

To create a task from a template:

<Steps>

1. Select **Create** → **From Template** and search for the template
2. Pick it to open a new task form pre-filled from the template
3. Adjust anything specific to this instance, such as the person being offboarded in the title, the assignee, and the due date, then save

</Steps>

The due date isn't copied, since each instance has its own deadline. Changes to the new task don't affect the template.

Templates don't show up in your normal task lists or counts. Use the **Templates** quick filter on the Tasks table to find, edit, or retire them; templates are marked with a **Template** badge.

### Bulk Task Creation

For many tasks at once, like a full evidence-request queue, import a CSV:

<Steps>

1. Open [Import tasks](https://console.theopenlane.io/import?type=task), or select **Bulk Upload** from the `...` menu on the [Tasks page](https://console.theopenlane.io/tasks)
2. Upload your CSV. `Title` is the only required column, and your column names don't need to match Openlane's.
3. Map your columns to task fields, remap any values your file spells differently (such as a status), and preview the tasks before importing

</Steps>

See [Import Data from CSV](../importing-data.mdx) for a walkthrough of each step. The field reference on the upload step lists every supported field and has an example CSV to download.

## What Teams Use Tasks For

| Use Case | Example |
| --- | --- |
| **Evidence requests** | "Upload the Q3 access review export for CC6.1" assigned to the platform lead, due before the audit window closes |
| **Policy reviews** | Annual review tasks for each policy owner, created in bulk at the start of the year |
| **Remediation** | A finding from a scan or gap analysis becomes a task with a deadline, linked to the risk it addresses |
| **Audit preparation** | Walkthrough scheduling, document collection, and auditor requests, tracked in one place |
| **Automated collection** | A developer wires the Openlane [Go client](https://github.com/theopenlane/go-client) into a CI/CD pipeline to create and close evidence tasks automatically |

## FAQ

<details>
<summary>When should something be a task versus a workflow?</summary>

A task is a single piece of work with an owner and a deadline. Recurring collection from many people at once (quarterly attestations, annual vendor reviews) fits a recurring [campaign](./campaigns.mdx), and changes that need review before they take effect fit a [workflow](./workflows/overview.mdx).

</details>

<details>
<summary>Can I assign a task to a group?</summary>

Tasks are assigned to individual users for clear accountability, but you can use [groups](../settings/groups/overview.mdx) to control who can see and manage them.

</details>
