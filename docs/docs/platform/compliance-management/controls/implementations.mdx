# Control Implementations

Control language is intentionally general. Consider this control:

```yaml
- category: Communication and Information
  subcategory: Information Quality
  refCode: CC2.1.3
  description: Logging and monitoring software is configured to collect events and alert personnel upon detection of unusual system activity.
  soc2Mapping:
    - CC2.1
```

The control states the requirement but not how your organization meets it, and that is deliberate: naming a specific tool like Grafana in the control text means editing the control every time you change tools. The control implementation holds the tool-specific and process-specific detail instead, so the control language stays stable and auditor-facing while the implementation records what your team actually runs, stored alongside the requirement it satisfies.

## Writing a Good Implementation

The implementation details are prose, and specificity is what makes them useful:

- **Vague (avoid):** "Logging and monitoring software is configured to collect events and alert personnel upon detection of unusual system activity."
- **Specific (aim for):** "Services are expected to have best-effort Prometheus-style metrics emitted with data representing thresholds for failure or success. Additionally, they should attempt to emit json formatted logs for ingesting into the GCP Log Sink."

## Verification and Evidence

Verification confirms the implementation works: someone tests the control (walkthrough, sample inspection, technical test) and records the result and date. From there, [evidence](../evidence/overview.mdx) proves it *keeps* working: recurring artifacts collected over the audit period.

A practical rhythm: verify when you first complete an implementation, attach the test results as <Term t="evidence">evidence</Term>, then let recurring [tasks](../../automation/tasks.mdx) drive evidence collection on schedule.

## How Implementations Connect

Each implementation belongs to a [control](./overview.mdx) (or subcontrol) and has an assignee: the person accountable for keeping it accurate. Because controls map to your enabled frameworks, one well-written implementation can serve the same requirement across System and Organization Controls 2 (SOC 2), ISO 27001, and anything else that maps to it.
