# Programs

A program is the container for a compliance effort with a defined goal and timeline: get System and Organization Controls 2 (SOC 2) ready, complete an ISO 27001 certification, run this year's risk assessment. It pulls the <Term t="controls">controls</Term>, <Term t="evidence">evidence</Term>, tasks, risks, and people for that effort into one place.

An audit is a deadline with a scope, and both live on the program. Scoping a SOC 2 audit means knowing which controls are in, what evidence covers the audit period, and who is responsible for what; the program holds all three.

Programs also keep concurrent efforts from blurring together. Your SOC 2 Type 2 and your ISO 27001 certification can share underlying work, but each has its own scope, timeline, and audit details.

## Creating a program

The program wizard walks you through setup and offers six starting points. The **Quickstart** templates set up a **SOC 2** program, a **Risk Assessment** program, or a **Framework Based** program (ISO 27001, Health Insurance Portability and Accountability Act (HIPAA), and others). The **Custom** options start **From Existing Program** to reuse its controls, auditor, and owner, start a blank **Generic Program**, or use **Advanced Setup** for full customization. If you chose frameworks during onboarding, the matching template is marked **Recommended** when you create your first program.

<CreateProgramPreview />

To create one:

1. From any page in the console, click the `+` button at the top of the side navigation bar
1. Select `Create Program` from the dropdown menu
1. Choose a template or custom option and follow the wizard prompts for the path you selected
1. Click `Create` to finalize the program

Framework-based programs come pre-populated with the relevant controls; a SOC 2 program additionally lets you include only specific domains (for example Security and Availability) if you don't want all of the Trust Services Criteria. Controls can be added or removed after creation from the program settings or the [standards catalog](https://console.theopenlane.io/standards), and any field you set in the wizard can be changed later from the programs page or program settings. The wizard choice gets you started; it doesn't lock you in.

## Program status

A program's status tracks the effort from planning through completion. The one behavior worth knowing in advance: a completed program stays completed as the record of that cycle, and the next cycle (next year's audit period, the annual risk assessment) starts as a new program, which keeps each cycle's scope, evidence period, and audit details distinct.

## Tracking program work

The **Work** tab on a program lists everything still to be done for it in one place. It covers every kind of object linked to the program, so you can see what is outstanding without opening each section of the console.

<ProgramWorkPreview view="table" />

### Work status

Each of those objects has its own status values, so the Work tab maps them onto four shared stages:

| Work status | Tasks | Controls | Evidence | Policies and procedures |
| --- | --- | --- | --- | --- |
| **Open** | Open | Not Implemented | Requested, Needs Renewal | None |
| **In Progress** | In Progress | Preparing, Draft, Changes Requested | Draft, Missing Artifact, Rejected | Draft |
| **In Review** | In Review | Needs Approval | Submitted, In Review | Needs Approval, Pending |
| **Completed** | Completed, Won't Do | Approved, Not Applicable, Archived | Ready for Auditor, Auditor Approved | Approved, Published, Archived |

By default the tab shows only outstanding work, which is anything not yet completed. When an item's own status says more than its stage, such as a control with changes requested or evidence that needs renewal, the **Attention** column shows it. Tasks past their due date also get an **Overdue** badge there.

### What each item shows

| Column | What it shows |
| --- | --- |
| Owner | The assignee for a task, the owner for a control, the approver for a policy or procedure, and the owners of the supported controls for evidence |
| Due date | The due date for tasks. Other objects do not carry one. |
| Related to | The control or framework the item belongs to |

Items are sorted by stage, with overdue tasks first and then the oldest items.

### Finding your work

The summary cards at the top count outstanding items by type. Click a card to show only that type, or click **Total** to show everything again. Switch between the **Table** and **Board** views to see the same items as a list or grouped into a column per stage.

Use the **My Work** quick filter to see items you own, or **Overdue tasks** to see tasks past their due date. The full filters cover status, object type, owner, and overdue tasks, and the search box matches names, titles, and ref codes.

<ProgramWorkPreview view="board" />

:::info
The Work tab loads up to 100 items per object type. When more than that match your filters, a message tells you how many are hidden. Narrow the filters to see the rest.
:::

## Working with auditors

Programs carry your audit details: the audit firm, the auditor, and the audit period. You can grant your auditor access directly during program setup, so evidence review happens in Openlane instead of through a third-party portal upload.

## How programs connect

A program scopes [controls](../controls/overview.mdx) from your enabled frameworks, coordinates [evidence](../evidence/overview.mdx) collection against the audit period, and tracks the work through [tasks](../../automation/tasks.mdx) and [risks](../../exposure/risks/overview.mdx). For the full field list, see the [GraphQL object reference](/docs/api/graph-api/). For framework-specific guidance, see the [Standards section](../../standards/overview.mdx).

## FAQ

<details>
<summary>Do I need one program per framework?</summary>

Usually, yes; each framework has its own scope, controls, and audit timeline. Work that overlaps (a control mapped to both SOC 2 and ISO 27001) doesn't get duplicated; both programs reference the same underlying controls and evidence.

</details>

<details>
<summary>Can I change what's in a program after creating it?</summary>

Yes. Controls can be added or removed at any time from the program settings or the standards catalog, and any field you set in the wizard can be changed later.

</details>

<details>
<summary>What's the difference between a program and a standard?</summary>

A standard is the framework itself: the catalog of requirements. A program is your organization's initiative against it: the scoped controls, the timeline, the team, and the audit.

</details>
