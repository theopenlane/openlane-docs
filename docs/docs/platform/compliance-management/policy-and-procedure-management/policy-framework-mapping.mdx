# Policies to Framework Mapping

Each framework has its own set of requirements, but the policies they expect overlap heavily. This page maps common policies to the frameworks that expect them, so you can see which documents you need for the standards you are pursuing and which ones will carry you across every framework you add later.

The core takeaway: a well-scoped set of foundational policies satisfies effectively every security and privacy framework. Framework-specific policies only enter the picture for specialized regimes (HIPAA's privacy rules, federal control catalogs, AI management standards, and the like).

In the table, **All** means the policy maps to effectively every commonly pursued framework, including SOC 2, ISO 27001, ISO 27701, NIST 800-53, NIST 800-171, NIST CSF, NIST AI RMF, PCI DSS, HIPAA, GDPR, CCPA/CPRA, CMMC, FedRAMP, DORA, NIS 2, COBIT, FFIEC, Cyber Essentials, CCM, CIS Controls, HITRUST, SOX ITGC, Microsoft SSPA, Essential Eight, and ISO 42001.

## How to Use This

If you are pursuing your first framework, start with the universal set: those policies are the working core of a compliance program, and every framework you add later will reuse them. Then add the framework-specific documents only for the regimes you actually operate under; there is no reason to maintain a Business Associate Policy if you never touch HIPAA.

Because one policy satisfies many frameworks, write each policy once and [map it to controls](../controls/mapping.mdx) across the standards you pursue rather than maintaining per-framework copies. See [Policies and Procedures](./policies.mdx) for guidance on consolidating and writing these documents, and the [import guide](./import.mdx) for bringing existing policies into Openlane.
