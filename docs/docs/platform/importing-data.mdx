# Import Data from CSV

Most teams arrive with records in spreadsheets or another tool: a vendor list, an asset inventory, a risk register. Openlane uses the same import everywhere, so you can upload the CSV you already have, map its columns to Openlane fields, fix any values that don't match, and preview the result before anything is created. You don't need to rename headers or reformat the file first, and your original file is never changed.

## What You Can Import

To start an import, select `Bulk Upload` from the `...` menu on the table you want to fill, such as vendors, assets, contacts, or risks.

To see every field a given import accepts, open the field reference link on its upload step, where you can also download an example CSV.

## How Import Works

The import walks you through three steps: **Upload**, **Map fields**, and **Review**. Nothing is created until you confirm on the last step. The illustrations below show a control import; every other import works the same way.

### 1. Upload

Drag and drop your CSV, or click to choose it. Files up to 10MB are accepted; comma, semicolon, tab, and pipe delimiters are detected automatically. Openlane reads the header row and lists the columns it found. If some rows have a different number of values than the header, you'll see a warning so you can check them in the preview before importing.

<ImportPreview step="upload" />

### 2. Map Fields

Each column in your file is shown with example values and a suggested Openlane field. Openlane matches columns for you by exact name, by known aliases (for example `Vendor Name`, `Company Name`, or `Account Name` all map to `Name`), and by names that differ only in wording. The **Match** column shows how each suggestion was made: `Exact`, `Alias`, `Suggested`, or `Manual` when you picked it yourself.

<ImportPreview step="map" />

- **Change a mapping**: pick a different field from the **Import as** dropdown, or choose `Ignore this column` to leave it out. Extra columns are fine and don't need to be deleted from your file.
- **Empty columns** are skipped automatically.
- **Filter and search**: use the `All`, `Mapped`, `Unmapped`, and `Issues` tabs, or search by column name, to work through large files.
- **Remap values in place**: if a column uses different terms than Openlane, such as `Done` or `In progress` for a status, Openlane flags the values it doesn't recognize. Open the value mapping for that column and choose which Openlane value each one should import as, or leave it blank. Close matches are suggested for you. If a column has more than 50 unrecognized values, fix those in the file instead.
- **Dates** in common formats such as `2/7/2026` or `Feb 7, 2026` are converted for you. When a date like `4/5/2026` could be read either way, a `M/D/Y` / `D/M/Y` toggle appears so you can pick the order your file uses.
- **Lists**, such as `Tags`, can be a JSON array (`["Security"]`) or values separated by `;`, `|`, or `,`.
- **Booleans** accept `true`, `false`, `yes`, or `no`.

Anything that would block the import, such as a missing required column, two columns mapped to the same field, or values that are still invalid, is listed at the top of the step with a `Fix` link that jumps to the column. `Continue` is enabled once every issue is resolved.

### 3. Review

The review step summarizes how many records will be created, how many fields are mapped, which columns are ignored, and what is set automatically, such as `Source: Imported`. A preview shows the first rows exactly as they will be imported, along with any values that were remapped or dates that were converted.

<ImportPreview step="review" />

Check the preview. If something looks wrong, click `Edit mapping` or `Back` to return to the previous step. When it looks right, click `Import`. When it completes, you'll see a success message and return to the table you started from.

## Importing Through the API

Each import is also available as a `createBulkCSV<Object>` GraphQL mutation, such as `createBulkCSVEntity` or `createBulkCSVRisk`, which accepts a CSV directly without the mapping step. When using the API, headers must match the field names exactly in `UpperCamelCase`, lists must be JSON (for example `["Security"]`), and JSON fields must have their quotes escaped. Download the example CSV from the console's field reference to start from the expected headers.
