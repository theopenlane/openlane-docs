# CC7.2

<ControlMeta
  refCode={"CC7.2"}
  category={"Security"}
  subcategory={"System Operations"}
  description={"The entity monitors system components and the operation of those components for anomalies that are indicative of malicious acts, natural disasters, and errors affecting the entity’s ability to meet its objectives; anomalies are analyzed to determine whether they represent security events."}
/>

## Points of Focus

<details>
<summary>Implements Detection Policies, Procedures, and Tools</summary>

Detection policies, procedures and tools are defined and implemented on Infrastructure and software to identify potential intrusions, inappropriate access and anomalies in the operation of or unusual activity on systems. Procedures may include- (1) a defined governance process for security event detection and management; (2) use of intelligence sources to identify newly discovered threats and vulnerabilities; and (3) logging of unusual system activities.

</details>

<details>
<summary>Designs Detection Measures</summary>

Detection measures are designed to identify anomalies that could result from actual or attempted (1) compromise of physical barriers; (2) unauthorized actions of authorized personnel; (3) use of compromised identification and authentication credentials; (4) unauthorized access from outside the system boundaries; (5) compromise of authorized external parties; and (6) implementation or connection of unauthorized hardware and software.

</details>

<details>
<summary>Implements Filters to Analyze Anomalies</summary>

Management has implemented procedures to filter, summarize, and analyze anomalies to identify security events.

</details>

<details>
<summary>Monitors Detection Tools for Effective Operation</summary>

Management has implemented processes to monitor and maintain the effectiveness of detection tools.

</details>

## Example Organization Controls

- **CC7.2.1** - Documented incident response and escalation procedures for reporting security incidents are in place to guide users in identifying, reporting and mitigating failures, incidents, concerns, and other complaints.
- **CC7.2.2** - Policies and procedures are in place regarding detection, logging, and monitoring of unknown or unauthorized components into the environment.
- **CC7.2.3** - The entity monitors key activities and alerts are generated when those activities are outside normal tolerances.
- **CC7.2.4** - Alerts are generated to those responsible for taking action.
- **CC7.2.7** - Suspected malicious traffic is tagged and blocked according to rulesets.

## Example Control Implementations

- **gitops-change-management** - All changes to production systems follow a GitOps workflow. Implementation includes: - All code and infrastructure configuration stored in GitHub repositories - Branch protection requires pull request review before merging - Buildkite CI runs automated tests, linting, and security scanning - ArgoCD deploys changes to GKE after Helm chart PR is approved - Rollback capability maintained through Git history and ArgoCD - Emergency changes require post-implementation review
- **centralized-logging** - Application and infrastructure logs are centrally aggregated. Implementation includes: - GCP Cloud Logging aggregates all application and infrastructure logs - Betterstack provides uptime monitoring and alerting - Grafana provides metrics visualization - Log retention follows Data Retention Policy (90 days active, 1 year archived) - Security events trigger alerts via Slack integration
