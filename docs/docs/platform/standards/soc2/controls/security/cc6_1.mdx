# CC6.1

<ControlMeta
  refCode={"CC6.1"}
  category={"Security"}
  subcategory={"Logical and Physical Access Controls"}
  description={"The entity implements logical access security software, infrastructure, and architectures over protected information assets to protect them from security events to meet the entity’s objectives."}
/>

## Points of Focus

<details>
<summary>Identifies and Manages the Inventory of Information Assets</summary>

The entity identifies, inventories, classifies, and manages information assets (for example, infrastructure, software, and data).

</details>

<details>
<summary>Assesses New Architectures</summary>

The entity identifies new system architectures and assesses their security prior to implementation into the system environment.

</details>

<details>
<summary>Restricts Logical Access</summary>

The entity restricts logical access to information assets, including infrastructure (for example, server, storage, network elements, APIs, and endpoint devices), software, and data (at rest, during processing, or in transmission) through the use of access control software, rule sets, and standard configuration hardening processes.

</details>

<details>
<summary>Identifies and Authenticates Users</summary>

The entity identifies and authenticates persons, infrastructure, and software prior to accessing information assets, whether locally or remotely. The entity uses more complex or advanced user authentication techniques such as multifactor authentication when such protections are deemed appropriate based on its risk mitigation strategy.

</details>

<details>
<summary>Considers Network Segmentation</summary>

The entity uses network segmentation, zero trust architectures, and other techniques to isolate unrelated portions of the entity's information technology from each other based on the entity's risk mitigation strategy.

</details>

<details>
<summary>Manages Points of Access</summary>

Points of access by outside entities and the types of data that flow through the points of access are identified, inventoried, and managed. The types of individuals and systems using each point of access are identified, documented, and managed.

</details>

<details>
<summary>Restricts Access to Information Assets</summary>

Combinations of data classification, separate data structures, port restrictions, access protocol restrictions, user identification, and digital certificates are used to establish access control rules and configuration standards for information assets.

</details>

<details>
<summary>Manages Identification and Authentication</summary>

Identification and authentication requirements are established, documented, and managed for individuals and systems accessing entity information, infrastructure and software.

</details>

<details>
<summary>Manages Credentials for Infrastructure and Software</summary>

New internal and external infrastructure and software are registered, authorized, and documented prior to being granted access credentials and implemented on the network or access point. Credentials are removed and access is disabled when access is no longer required or the infrastructure and software are no longer in use.

</details>

<details>
<summary>Uses Encryption to Protect Data</summary>

The entity uses encryption to protect data (at rest, during processing, or in transmission), when such protections are deemed appropriate based on the entity's risk mitigation strategy.

</details>

<details>
<summary>Protects Cryptographic Keys</summary>

The entity protects cryptographic keys during generation, storage, use, and destruction. Cryptographic modules, algorithms, key lengths, and architectures are appropriate based on the entity's risk mitigation strategy.

</details>

<details>
<summary>Restricts Access to and Use of Confidential Information for Identified Purposes</summary>

Logical access to and use of confidential information is restricted to identified purposes.

</details>

<details>
<summary>(Privacy Criteria Only) Restricts Access to and the Use of Personal Information</summary>

Logical access to and use of personal information is restricted to authorized personnel who require such access to fulfill the identified purposes to support the achievement of the entity's objectives related to privacy.

</details>

## Example Organization Controls

- **CC6.1.1** - An inventory of system assets and components is maintained to manage the information assets.
- **CC6.1.2** - Documented policies and procedures are in place regarding system settings, authentication, access, and security monitoring.
- **CC6.1.3** - System access is restricted to authorized individuals commensurate with their job responsibilities.
- **CC6.1.4** - Predefined security groups are utilized to assign role-based access privileges and segregate access.
- **CC6.1.5** - Network segmentation and IP restrictions are in-place to ensure logical access is also enforced by origin address.
- **CC6.1.6** - Endpoints are secured using TLS encryption.

## Example Control Objectives

- **Access control enforcement** - Access to systems and data is restricted to authorized individuals through proper provisioning and deprovisioning controls.

## Example Control Implementations

- **identity-provider-sso** - Access control is implemented through Google Workspace as the primary identity provider. All employee accounts are managed centrally with single sign-on (SSO) integration to business applications. Implementation includes: - Google Workspace serves as the identity provider for all employees - SSO is configured for GitHub, GCP Console, AWS Console, Slack, Notion, and other tools - Multi-factor authentication (MFA) is enforced organization-wide via Google Workspace security policies - User provisioning and deprovisioning follow documented onboarding/offboarding procedures
- **secret-management** - Secrets are managed through dedicated secret management tools. Implementation includes: - Production secrets stored in GCP Secret Manager - Development credentials stored in 1Password - GitHub secret scanning enabled on all repositories - API keys rotated quarterly per Password Policy - Service accounts audited quarterly during access reviews
- **encryption-at-rest-transit** - All data is encrypted at rest and in transit. Implementation includes: - TLS 1.2+ required for all external connections - Cloudflare provides TLS termination and certificate management - Cloud SQL encryption at rest with Google-managed keys - S3 server-side encryption for evidence storage - Employee devices require full disk encryption (FileVault/BitLocker)
