# ![microsoft defender for cloud integration](./assets/azure.png) Microsoft Defender for Cloud integration guide

Microsoft Defender for Cloud assesses the resources in your Azure subscriptions and flags what is misconfigured or out of date. Connect it to Openlane when you want those results tracked as <Term t="finding">findings</Term> and vulnerabilities in the same program as your controls, with remediation owners and due dates.

## Key capabilities

Openlane collects the posture assessments Defender for Cloud marks as unhealthy and records each one as a finding, with the affected resource and a link back to the Azure portal. Recommendations to update software or upgrade a service carry their CVEs, so they arrive as vulnerability records instead. If you use Defender for Cloud regulatory compliance standards such as SOC 2, Openlane can also record each compliance assessment as a check against the control it tests.

Access is read-only. Openlane reads security data from your subscriptions and never changes resources, policies, or Defender for Cloud settings.

## Prerequisites

* Microsoft Defender for Cloud enabled on each subscription you want to collect from
* For the Azure Lighthouse option, an account with the **Owner** role on each subscription
* For the admin consent option, an account that can grant tenant-wide admin consent, plus permission to assign roles on each subscription

## Step-by-step setup

### Step 1: Choose how to grant access

Openlane offers two ways to connect, and both give Openlane the built-in **Security Reader** role and nothing more. We recommend Azure Lighthouse because the access lives on each subscription you delegate, appears under **Service providers** in the Azure portal, and is removed from Azure when you disconnect in Openlane. Admin consent suits teams that already manage third-party access through enterprise applications.

#### Option A: Azure Lighthouse (recommended)

<Steps>

1. Go to **Automation** > **Integrations**, find **Microsoft Defender for Cloud**, and click **Configure**.
1. Select **Azure Lighthouse**. The form shows a connection code and a template to deploy in Azure. Copy the template.
1. In the Azure portal, open **Service providers** > **Service provider offers** and select **Add offer** > **Add via template**.
1. Paste the template, choose the subscription to delegate, and enter the connection code from Openlane as the `connectionCode` parameter. A subscription Owner deploys the template once for each subscription you want Openlane to read.
1. Wait until the Openlane Defender for Cloud offer appears under **Service provider offers**.
1. Back in Openlane, enter your Microsoft Entra tenant ID and submit the form.

</Steps>

Openlane checks that at least one subscription in your tenant is delegated with your connection code before it saves the connection. To add a subscription later, deploy the same template on it with the same connection code.

#### Option B: Azure admin consent

<Steps>

1. Go to **Automation** > **Integrations**, find **Microsoft Defender for Cloud**, and click **Configure**.
1. Select **Azure Admin Consent** and click **Continue to Authorization**. You will be redirected to Microsoft.
1. Sign in with an account that can grant admin consent and approve the request. You are redirected back to Openlane and the connection is saved.
1. In the Azure portal, open each subscription you want Openlane to read, go to **Access control (IAM)**, and assign the **Security Reader** role to the Openlane enterprise application. The application ID is shown on the Openlane connection form.

</Steps>

The connection saves before the role is assigned, so collection returns no data until you finish the last step.

### Step 2: Configure collection

Optionally narrow what Openlane collects:

| Setting | Description |
|---|---|
| **Subscription IDs** | Limit collection to these subscriptions. Leave it empty to collect from every subscription Openlane can read |
| **Compliance Standards** | Limit compliance assessment collection to these standards. Leave it empty to collect every standard enabled in Defender for Cloud |
| **Collect Checks** | Record every compliance assessment as a check linked to its control. When it is off, Openlane collects only failed assessments that have no matching Defender for Cloud recommendation, as findings |

## Validate connection

After saving, Openlane runs a health check that confirms it can read Defender for Cloud assessments and displays the result on the **Installed** tab of the Integrations page. You should see a **Healthy** badge. If the badge shows **Needs Attention**, review the troubleshooting section below.

## What Openlane syncs

Openlane collects on a recurring schedule, and each sync updates the records from the previous one instead of creating duplicates. The data feeds your vulnerability management program and gives you evidence for technical vulnerability handling controls:

* Unhealthy security posture assessments, as findings, with the affected resource and the owner from any Defender for Cloud governance assignment
* Software update and service upgrade recommendations, as one vulnerability record per CVE
* Regulatory compliance assessment results, as checks linked to their controls when **Collect Checks** is on, and as findings when they fail without a matching recommendation

## Disconnect

To remove this integration, go to **Automation** > **Integrations** and select the **Installed** tab. Open the menu on the integration card and select **Disconnect**. Collection stops and Openlane removes its stored connection.

What happens in Azure depends on how you connected. For an Azure Lighthouse connection, Openlane also removes its delegation from every subscription delegated with your connection code. If that removal fails, remove the Openlane Defender for Cloud offer from **Service providers** in the Azure portal. For an admin consent connection, remove the Openlane enterprise application and its subscription role assignments in Azure to revoke access fully.

## Troubleshooting

If an Azure Lighthouse connection does not save, the template was usually deployed with a different connection code, or the deployment has not finished. Confirm that the Openlane Defender for Cloud offer appears under **Service provider offers** for at least one subscription and that its name ends with the code shown in Openlane.

When the connection is healthy but no data arrives, confirm that Defender for Cloud is enabled on the subscription. For an admin consent connection, also confirm that the **Security Reader** role is assigned to the Openlane enterprise application on that subscription. A single missing subscription usually means **Subscription IDs** leaves it out or, for Azure Lighthouse, that the template has not been deployed on it yet.
